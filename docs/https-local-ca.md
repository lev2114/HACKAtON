# HTTPS без предупреждения браузера (свой локальный CA)

Сервер при первом запуске сам генерирует **два** файла (в `server/`,
оба в `.gitignore`, не коммитятся):

- `ca-cert.pem` — публичный сертификат локального удостоверяющего центра.
  **Этот файл нужно раздать** на каждый ноутбук-клиент.
- `ca-key.pem` — приватный ключ этого CA. **Никогда никому не передавать**,
  остаётся только на сервере. Им подписан `server/cert.pem` — реальный
  сертификат, который сервер показывает браузеру.

Пока `ca-cert.pem` не добавлен в доверенные у конкретного клиента, браузер
на этой машине будет показывать обычное предупреждение "соединение не
защищено" — это ожидаемо, игра при этом полностью работает, просто
доверие не настроено. После импорта предупреждение пропадает, в адресной
строке — закрытый замок.

## Шаг 1 — скопировать `ca-cert.pem` с сервера на каждый клиент

Любым способом: флешка, чат команды, `scp`, общая папка. **Только
`ca-cert.pem`**, не `ca-key.pem`.

## Шаг 2 — импортировать на каждом ноутбуке-клиенте (и на самом сервере, если заходите с него же в браузер)

### Windows — без прав администратора (только для вашего пользователя)

```powershell
certutil -addstore -user -f ROOT ca-cert.pem
```

### Windows — для всех пользователей машины (нужны права администратора)

Открыть PowerShell/cmd **от имени администратора**, затем:

```powershell
certutil -addstore -f ROOT ca-cert.pem
```

### Windows — через интерфейс (если `certutil` не работает/не хочется консоль)

1. Дважды кликнуть по `ca-cert.pem`.
2. "Установить сертификат..." → "Текущий пользователь" (без прав админа)
   или "Локальный компьютер" (нужны права админа, спросит подтверждение).
3. "Поместить все сертификаты в следующее хранилище" → Обзор →
   **"Доверенные корневые центры сертификации"**.
4. Готово, подтвердить предупреждение системы безопасности (это Windows
   спрашивает "вы точно доверяете этому сертификату" — да, это наш же CA).

### macOS

```bash
sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain ca-cert.pem
```

## Шаг 3 — перезапустить браузер на клиенте

После импорта закрыть и заново открыть Chrome/Edge на клиентской машине
(уже открытые вкладки могли закэшировать старое состояние доверия).
Зайти на `https://<адрес сервера>:8080` — должен быть зелёный замок без
предупреждений.

## Если сертификат перегенерировался

Сервер переиспользует `ca-cert.pem`/`ca-key.pem`/`cert.pem`/`key.pem`
между запусками (не трогает, если все четыре файла на месте). Если
удалить `server/station.db` и сертификаты вместе (например, полностью
чистый старт) — сгенерируется НОВЫЙ CA, и импорт на клиентах нужно будет
повторить с новым `ca-cert.pem`. Если нужно гарантированно не перегенерировать
сертификаты между демо-прогонами — просто не удалять `server/*.pem`.

## Если лень возиться с импортом

Можно просто ничего не делать — самоподписанная цепочка всё равно
работает, трафик (включая пароли) всё равно шифруется, просто на каждом
клиенте браузер спросит подтверждение один раз при первом заходе
("Дополнительно" → "Перейти на сайт"). Для хакатон-демо это тоже
нормально, см. `PROTOCOL.md` → раздел "HTTPS".
